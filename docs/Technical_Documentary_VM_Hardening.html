InsightEd Infrastructure: Permanent VM Hardening & Self-Healing Protocol

This document serves as the official structural record for the transition of the InsightEd ecosystem (Staging & Production) to a persistent, self-healing state on the VM 20.24.58.49.

I. Architecture: The Single Source of Truth

Prior to April 4th, 2026, environment configurations were stored in disparate VM environment variables and manual PM2 start commands. We have now consolidated all lifecycle management into a version-controlled ecosystem config.

1. Unified PM2 Ecosystem

The ecosystem.config.cjs file now acts as the authoritative record for ports and paths:

module.exports = {
  apps: [
    {
      name: "insighted-staging", // Port 5001
      env: { UPLOAD_DIR: "/tmp/insighted-pdf-tmp" }
    },
    {
      name: "insighted-backend", // Port 5000 (Production)
      env: { UPLOAD_DIR: "/tmp/insighted-pdf-tmp" }
    }
  ]
};

II. The Forensic Healing Protocol

Every deployment now triggers a Forensic Audit. This ensures that even if a server process crashes or a config is accidentally modified, the system reverts to the correct state automatically.

Self-Healing Success: The forensic script now automatically detects and kills root-owned zombie processes that previously blocked deployments.

III. Hardened Nginx Proxy (ADR-003/009)

Nginx configurations have been synchronized to eliminate "Gateway Timeout" errors during large PDF uploads. The following hardening directives are now permanent:

  • Optimized Buffering: proxy_request_buffering off; (Ensures immediate data streaming to backend).
  • Extended Upstream Timeouts: All proxy timeouts synchronized at 600s.
  • Security: All asset access forced through /api/asset/:id; direct disk access blocked.

IV. Summary of Impact

The implementation of the heal:production and heal:staging workflows marks a shift from reactive maintenance to proactive infrastructure stability. The standard deployment scripts (deploy-local.sh) are now inherently resilient.
