Production Infrastructure Hardening

High-Concurrency & Performance Optimization Protocol

Version: 1.1 | Reference: ADR-007 | Status: PRODUCTION READY

1. Executive Summary

This document details the architectural hardening implemented to support 500+ concurrent burst users on the InsightEd production environment. The strategy prioritizes Event Loop Protection, I/O Smoothing, and Transactional Atomic Integrity.

2. Nginx Concurrency & Event Model

To prevent socket exhaustion and effectively balance incoming requests, the Nginx event model has been upgraded to the high-performance epoll model.

Core Optimizations:

  • worker_connections 10240: Scales to handle massive connection surges.
  • use epoll: Utilizes the kernel's most efficient polling method for high-load Linux environments.
  • multi_accept on: Allows worker processes to accept multiple new connections in a single loop, minimizing race conditions on the accept lock.
  • keepalive_requests 10000: Maintains persistent TCP connections longer, reducing SSL handshake overhead.
  • open_file_cache: In-memory caching for file descriptors to reduce system-call overhead.

4. High-Throughput Database Architecture

PostgreSQL write operations have been smoothed to prevent disk I/O spikes during concurrent survey submissions, and PgBouncer has been hardened for prepared statement mapping.

Parameter Value Impact
max_wal_size 16GB Reduces checkpoint frequency during heavy data ingestion.
wal_compression on Compresses WAL pages to reduce physical disk I/O throughput.
checkpoint_timeout 15min Spreads the physical write burden over a longer interval.
completion_target 0.9 Instructs Postgres to take 90% of the timeout window to flush data.
checkpoint_flush_after 512kB Prevents large kernel page cache stalls during fsync.

PgBouncer & Prepared Statements

Configured max_prepared_statements = 200 in pgbouncer.ini. This allows the Node.js application to retain the performance benefits of prepared statements while utilizing transaction pooling mode—a critical requirement for 500+ concurrent users.

6. Real-Time Telemetry & Monitoring

A specialized monitor script has been deployed to verify and track all 16 Hardening Factors in real-time.

Monitor Script: fave_scripts/hardening_monitor.py

  • Connectivity: Live tracking of Nginx (Port 443) and PgBouncer (Port 6432) availability.
  • Admission Health: Displays real-time 503 load-shedding activity.
  • PM2 Stability: Monitors RSS memory usage against the 1GB restart threshold.
  • WAL Integrity: Verifies smoothed checkpoint execution and high-water markers.

7. Schema & Index Efficiency

To further reduce write latency, redundant indices have been pruned and missing performance markers added.

  • Redundant Pruning: Removed overlapping global B-tree indices on high-volume search columns.
  • Strategic Marker: Added ph_schools(region, division) compound index to accelerate regional dashboard aggregation.
