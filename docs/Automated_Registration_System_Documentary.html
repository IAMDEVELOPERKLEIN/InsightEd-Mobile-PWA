SYSTEM DOCUMENTARY

PROTOCOL: AUTOMATED REGISTRATION | VERSION 2.0 | ROLE: SDO PORTAL

This technical documentary outlines the architectural evolution of the school registration pipeline within the InsightEd ecosystem, transitioning from a manually approved request system to a high-speed automated registry.

1. The Automated Approval Engine

The system utilizes an Atomic Transaction Model. When a School Division Office (SDO) personnel submits a registration form, the backend executes a self-contained SQL transaction that simultaneously logs the audit trail and activates the master registry.

BEGIN;
  INSERT INTO pending_schools (...) VALUES (...); -- Status: 'approved'
  -- IERN GENERATION LOGIC
  INSERT INTO "schools_IERN" (...) VALUES (...); -- Active Registry
COMMIT;

2. Sequential IERN Generation

Data integrity is maintained through a regex-hardened ID generator. This prevents the sequence from being polluted by legacy test entries (e.g., SDO-164000).

1
Pattern Matching: The engine filters for valid IERNs using the Postgres Regex: ~ '^[0-9]{4}-[0-9]+$'
2
Increment Logic: The system identifies the last numeric suffix (e.g., 45998) and increments it while dynamically prepending the current system year.

3. Field-Level Validation Logic

Master Identity Check

As the SDO types a 6-digit School ID, the system performs a real-time GET /api/sdo/check-id/:id request against the schools_IERN table. Duplicates are blocked instantly.

Naming Standard Enforcement

Common abbreviations are strictly forbidden to ensure report consistency. Restricted tokens include:

ES, NHS, PS, CS, CES, HS, IS, SHS, ELEM, MNHS

4. Self-Healing Registry Schema

To support high-fidelity mapping and parent-school relationships, the system automatically patches the database schema on server startup:

ALTER TABLE "schools_IERN" 
ADD COLUMN IF NOT EXISTS "Latitude" NUMERIC(10, 7),
ADD COLUMN IF NOT EXISTS "Longitude" NUMERIC(10, 7),
ADD COLUMN IF NOT EXISTS "Mother_School_ID" TEXT;

5. Security & Access Protocol

The system implements a strict RBAC (Role-Based Access Control) policy. Access to the SchoolManagement module is limited to accounts holding the School Division Office role. Any unauthorized attempts are logged and redirected to the primary monitoring dashboard.
