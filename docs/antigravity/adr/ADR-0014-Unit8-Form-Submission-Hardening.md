# ADR-0014: Unit 8 Form Submission Hardening

## Status
**Implemented — 2026-04-11**

## Context

Unit 8 (School Terrain & Location Profile) submission was failing silently for a subset of users on certain devices. The root causes spanned three layers — frontend gate logic, Zod schema strictness, and a faulty DB migration USING clause — none of which produced a visible error message to the user before this fix.

## Decisions

### 1. Reference-Point Gate: SUM > 0, not ALL non-zero

The `isStep3Valid()` function and `nextStep()` guard now use `reduce(...sum) > 0` instead of `some(val === 0)`. This matches the server-side check in `onSubmit` and correctly allows schools that legitimately have a 0 km or 0 min value for one or more services (e.g., a school directly at the barangay hall).

**Rule going forward:** Any frontend field-completeness guard must mirror the server-side validation logic exactly. Duplicate guard logic must not diverge.

### 2. safeBoolean Preprocessor for All Boolean Schema Fields

`z.boolean().optional()` is too strict for a mobile PWA where device browsers and offline-sync paths can deliver checkbox values as strings. The `safeBoolean` preprocessor (modelled after the existing `safeNumeric`) is now the standard for any optional boolean field in a Zod schema that touches a form input.

**Rule going forward:** Never use bare `z.boolean()` for form input fields. Always use `safeBoolean`.

### 3. road_paved_pct Auto-Correction via .transform()

Rather than relying on the browser slider to fire correctly, the server now auto-derives `road_unpaved_pct = 100 - road_paved_pct` in a `.transform()` step before validation. This makes the constraint self-healing regardless of the client device.

**Rule going forward:** When two fields must sum to a constant (complementary percentages), derive one from the other server-side via `.transform()` rather than enforcing the constraint purely via `.refine()`.

### 4. JSONB Migration USING Clause: Branch on data_type

`to_jsonb(col)` is only correct for `TEXT[]` (PG native array) columns. For `TEXT` columns storing JSON string literals, the correct cast is `col::jsonb`. The migration now branches on `information_schema.columns.data_type = 'ARRAY'`.

**Rule going forward:** Any boot-level migration that coerces TEXT to JSONB must distinguish between `TEXT` and `TEXT[]` source types and apply the appropriate USING expression.

### 5. Structured Inline Error Panel Replaces alert()

`alert()` is banned for async form submission errors. The error state is now a typed object `{ type, title, lines[] }` rendered as a persistent, dismissible `motion.div` panel with colour-coded severity (amber = validation, rose = server, slate = network). PostgreSQL diagnostic fields (`code`, `detail`, `constraint`, `table`) returned by the API are surfaced directly in the panel.

**Rule going forward:** All form submission error paths must display errors inline (never via `alert()`), must surface the full server error payload, and must use `console.error` (not `console.groupCollapsed`) so errors are visible immediately in DevTools.

## Consequences

- **Positive:** Users with legitimate zero-value reference points (e.g., school adjacent to a service) can now submit.
- **Positive:** Devices with range-input quirks or checkbox string coercion no longer produce silent 400 errors.
- **Positive:** DB migration is now correct for both TEXT and TEXT[] source column types.
- **Positive:** Engineers can now see the exact Zod field path, error code, and PG constraint directly in the UI without needing to open DevTools.
- **Negative (minor):** The `.transform()` silently overrides whatever value the client sent for `road_unpaved_pct`. This is intentional — the paved percentage is the authoritative input; the unpaved is derived.
- **Pre-existing gap:** `autoMigrate()` lacks `pg_try_advisory_lock`. See session summary for details.
