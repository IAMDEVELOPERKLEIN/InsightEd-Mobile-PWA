# ADR-0002: Zod Validation Layer (Resilience v6.0)

## Status
**Proposed & Implemented (2026-03-28)**

## Context
The `api/index.js` monolith used primitive manual null-checks for registration and other critical JSON payloads. This approach offered no protection against type mismatches or malformed strings, leaving the PostgreSQL catalog vulnerable to bloat and ensuring higher maintenance overhead as the app scale reached 1000+ users.

## Decision
Introduce a centralized Zod validation layer at the top of the monolith to enforce strict schema compliance for all data entry points.

### Implementation Details:
- **Location**: In `api/index.js`, directly after imports.
- **Schemas**: `RegisterUserSchema`, `RegisterSchoolSchema`, `RegisterBetaSchema`, `PasscodeSchema`.
- **Method**: Use `.safeParse(req.body)` and return descriptive `400 Bad Request` responses with specific field errors.

## Consequences
- **Positive**: Hardens the API boundary against malformed requests.
- **Positive**: Normalizes email strings (lowercase, trimmed) automatically.
- **Positive**: Improves error reporting for developers and automated testing tools.
- **Neutral**: Adds a small performance overhead (validation), which is negligible compared to DB latency.
