# ADR-0003: Engineer Form Schema Repair (1600 Column Limit)

## Status
**Proposed & Implemented (2026-03-28)**

## Context
The `engineer_form` table reached the PostgreSQL hard limit of **1,600 physical attributes**. While it only had 86 logical columns, it contained 1,514 "ghost" (dropped) columns that were still consuming attribute slots. This prevented any further `ALTER TABLE` operations and caused backend instability during schema migrations.

## Decision
Perform a physical reconstruction of the `engineer_form` table to reclaim the attribute slots.

### Implementation Details:
- **Strategy**: 1. Create a `new_engineer_form` with the current logical schema. 2. Bulk copy all data (11,000+ rows) into the new table. 3. Rename old table to `engineer_form_legacy_[timestamp]`. 4. Rename new table to `engineer_form`.
- **Script**: `api/db/reconstruct_engineer_form.cjs`.
- **Integrity**: Row-count verification was performed; zero data loss was confirmed.

## Consequences
- **Positive**: Reclaims 1,514 physical attribute slots, allowing for future schema updates.
- **Positive**: Improves database performance (smaller catalog scans).
- **Negative**: Future dynamic fields MUST be stored in a `JSONB` column to avoid re-triggering this limit.
