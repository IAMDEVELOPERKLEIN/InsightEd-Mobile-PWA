# ADR-0007: PDF Pipeline Scratch Directory (Replacing `/mnt/uploads`)

## Status
**Implemented — 2026-04-04**

## Context

The PDF compression and Hydra transformation pipeline (`compressBufferTo96Dpi` in `api/index.js`) requires a writable local directory to stage temp files for the Python subprocess (`compress_pdf.py`). The flow is:

```
Buffer (memory) → write comp_in_*.pdf → Python compresses → read comp_out_*.pdf → upsertBinary() → Postgres
```

Temp files exist for seconds and are deleted immediately after. They are **not** storage — they are a bridge between Node.js memory and the Python subprocess, which requires file paths rather than stdin streams.

Previously, `UPLOAD_DIR=/mnt/uploads` was set in the staging `.env`. The PM2 process user (`Administrator1`) did not have write access to `/mnt/uploads`, causing `EACCES` on every PDF upload and silently bypassing all Hydra transformations.

## Decision

The `UPLOAD_DIR` environment variable now points to `/tmp/insighted-pdf-tmp` on the staging VM. This directory:
- Is created by `deploy-staging.sh` on every deploy (`mkdir -p /tmp/insighted-pdf-tmp && chmod 775`)
- Is owned by `Administrator1:www-data`
- Contains **no permanent data** — only `comp_in_*`, `comp_out_*`, and `hydra_*` scratch files
- Is cleared on VM reboot (acceptable — files are transient by design)

On localhost, `UPLOAD_DIR` is not set, so `UPLOAD_BASE_PATH` defaults to `./uploads` relative to the app directory, which is always writable.

## Consequences

- **Positive**: Eliminates `EACCES` errors. PDF compression and Hydra sharding now work on staging.
- **Positive**: Semantically accurate — the directory is explicitly a temp pipeline stage, not an asset store.
- **Positive**: VM reboots clear the dir automatically, preventing temp file accumulation.
- **Negative**: If the VM reboots between a write and a read within a single upload request, the temp file would be lost. This is acceptable because the entire upload is a single synchronous async chain — a reboot mid-upload would fail the request anyway.
- **Constraint**: Nginx must NOT serve `/tmp/insighted-pdf-tmp` as a static directory. All assets are exclusively served via `/api/asset/:id` from Postgres.

## Related

- `forensic_heal.sh` Phase 2: Creates temp dir, injects `UPLOAD_DIR` into `ecosystem.config.cjs`
- `deploy-staging.sh`: Creates temp dir on every deploy
- `tmp_stride.conf`: `location ^~ /uploads/ { return 410; }` blocks any legacy disk path requests
