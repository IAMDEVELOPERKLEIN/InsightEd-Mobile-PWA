# ADR-0001: State-Aware Migration Tracking System

## Status
**Proposed & Implemented (2026-03-28)**

## Context
The `api/index.js` monolith performed approximately 60 sequential database operations on every startup to verify table existence and column schema. With the Azure PostgreSQL instance having a 30-100ms RTT, this caused a ~58-second startup delay. Additionally, redundant backfills (IERN, Provinces) were consuming significant resources and logs.

## Decision
Implement a persistent tracking table `ph_migrations` to store the completion state of major migration phases.

### Implementation Details:
- **Tracking Table**: `CREATE TABLE IF NOT EXISTS ph_migrations (phase_name TEXT PRIMARY KEY, completed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP)`
- **Guard Function**: A helper `isMigrationRun(phaseName)` checks the table before executing expensive code blocks.
- **Phases Tracked**: `IERN Migration`, `Masterlist Province Sync`.

## Consequences
- **Positive**: Startup time reduced by ~90% (<5s).
- **Positive**: Terminal logs are cleaner and more focused.
- **Negative**: Future schema changes that modify these "phases" must explicitly delete the tracking row to re-trigger the migration if necessary.
